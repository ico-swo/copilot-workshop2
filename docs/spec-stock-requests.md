# Specification — Stock request module (Lab 2)

A workshop technician raises a **stock request** to draw parts from a warehouse for a
repair job. A warehouse operator approves or rejects it. Approval reduces stock.

Do not implement this by hand. Attach it to Copilot in Agent mode with
`#file:docs/spec-stock-requests.md`.

## Domain

| Field | Type | Rules |
|---|---|---|
| `id` | string | UUID, generated by the service |
| `reference` | string | `SR-YYYY-NNNN`, sequential per calendar year |
| `partId` | string | Must reference an existing, active part |
| `quantity` | integer | Greater than 0, at most 500 |
| `requestedBy` | string | 1–120 characters |
| `jobReference` | string \| null | Optional, at most 40 characters |
| `status` | enum | `pending`, `approved`, `rejected`, `cancelled` |
| `note` | string \| null | Optional, at most 240 characters |
| `decidedBy` | string \| null | Set when the request leaves `pending` |
| `version` | integer | Starts at 1, incremented on every change |
| `createdAt` | string | ISO 8601 UTC |
| `decidedAt` | string \| null | Set when the request leaves `pending` |

## State machine

Use an `ALLOWED_TRANSITIONS` map like the purchase-orders module, and serve it at
`GET /api/stock-requests/transitions`.

```
pending -> approved | rejected | cancelled      (all three are terminal)
```

## Business rules

1. Unknown or inactive `partId` → **400**, with the field in `error.details`.
2. `quantity` above current `stockQuantity` → **409** `insufficient_stock`.
3. Approval re-checks availability at approval time; if it is no longer available → **409**.
4. Approval decrements stock. Status change and decrement happen in **one transaction**.
5. A request no longer `pending` cannot be decided again → **409** `already_resolved`.
6. Only the person named in `requestedBy` may cancel their own pending request → otherwise **403**.
7. Create, approve, reject and cancel require `operator`. Reading requires `viewer`.
8. Every transition records an audit event: `stock_request.created`, `.approved`, `.rejected`, `.cancelled`.

## Endpoints

| Method | Path | Role | Behaviour |
|---|---|---|---|
| `GET` | `/api/stock-requests` | viewer | List with `status`, `partId`, plus `limit`, `offset`, `sort`, `direction` |
| `GET` | `/api/stock-requests/transitions` | viewer | The state machine |
| `GET` | `/api/stock-requests/:id` | viewer | One request, or 404 |
| `POST` | `/api/stock-requests` | operator | Create → **201** |
| `POST` | `/api/stock-requests/:id/approve` | operator | Approve and decrement stock |
| `POST` | `/api/stock-requests/:id/reject` | operator | Reject with a reason |
| `POST` | `/api/stock-requests/:id/cancel` | operator | Cancel your own pending request |

## Schema addition

```sql
CREATE TABLE IF NOT EXISTS stock_requests (
  id            TEXT PRIMARY KEY,
  reference     TEXT NOT NULL UNIQUE,
  part_id       TEXT NOT NULL REFERENCES parts (id) ON DELETE RESTRICT,
  quantity      INTEGER NOT NULL CHECK (quantity > 0 AND quantity <= 500),
  requested_by  TEXT NOT NULL,
  job_reference TEXT,
  status        TEXT NOT NULL CHECK (status IN ('pending', 'approved', 'rejected', 'cancelled')),
  note          TEXT,
  decided_by    TEXT,
  version       INTEGER NOT NULL DEFAULT 1,
  created_at    TEXT NOT NULL,
  decided_at    TEXT
);
CREATE INDEX IF NOT EXISTS idx_stock_requests_status ON stock_requests (status);
```
